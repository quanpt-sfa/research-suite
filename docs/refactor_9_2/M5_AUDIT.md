runs on every platform (it fails on Linux before the fix). Also add a CI-status check to the milestone procedure: a milestone is not reported as
met while `main` is red. Work package WP0 in `M5_WORK_PACKAGES.md`.

Lesson recorded: the M3 and M4 reports said "all tests pass" from local Windows runs while CI was red. From M5 on, every milestone report quotes the
CI run id it relies on.

## C. What the audit changes in the earlier M5 draft

* Concurrency: the draft assumed the store already gave optimistic concurrency. It does for proposals only; engine writes need `expected_head`.
* Invalidation: the draft planned new propagation. `graph/dependency.py` already does it for graph edges; M5 only has to make its outputs graph objects.
* CI: the draft did not know CI was red. WP0 is now the first package and blocks every other package's Definition of Done.
* Graph relations are fixed by a SQL CHECK on `edges.relation` (`state/schema.py:72,156`); the draft's idea of new relations would have required
  rebuilding `edges` in every store. M5 uses `depends_on` / `derived_from` with an `edge_kind` in provenance instead.
* `check_result_change_impact` is shallower than its name: it lists claims and three workflow names; Gate M test G cannot rely on it.
